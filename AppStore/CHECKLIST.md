# Публикация в Mac App Store — состояние и оставшиеся шаги

Сделано:

- приложение проверено вживую владельцем: автозамена, смена раскладки, перевод выделенного, терминал;
- идентификатор `com.alexey.duzhev.raskladushka` зарегистрирован в аккаунте разработчика;
- `Tools/release.sh` собирает и подписывает пакет для App Store (`build/export/Раскладушка.pkg`),
  с `--upload` — загружает его;
- `Tools/appstore/publish.py` заполняет карточку (тексты RU/EN, категории, возраст 4+, бесплатно, все страны,
  контакт и заметки для проверки, 4 скриншота на язык, выпуск сразу после одобрения) и с `--submit`
  отправляет на проверку;
- страницы поддержки и политики свёрстаны в `Site/`.

Состояние на 24 ноября 2026: версия 1.0.0 (сборка 1) отклонена 23 ноября по п. 2.4.5 («Универсальный доступ»
используется не для целей доступности). Что изменено к повторной отправке — в конце файла.
Отправка 11 ноября 2026: версия 1.0.0 (сборка 1), выпуск — сразу после одобрения.
Запись приложения: App Store Connect, id 6833656263. Сайт: https://itbali.github.io/raskladushka-site/
(репозиторий `itbali/raskladushka-site`, исходники страниц — папка `Site/`). В «Конфиденциальности приложения»
опубликовано «Сбор данных не ведётся».

Следующая версия: поднять `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` в `project.yml`, затем
`Tools/release.sh --upload` → дождаться обработки → `python3 Tools/appstore/publish.py --submit`.

## Риск отказа — честно

По словам инженеров Apple на форуме разработчиков, перехват «только чтение» и отправка нажатий в песочнице
разрешены (в этой сборке вживую не проверено, см. п. 1). Но проверка Apple к таким программам непоследовательна:

- другой переключатель раскладки (Switcher3way) в сентябре 2026 получил отказ по п. 2.4.5: запрос
  «Мониторинга ввода» сочли неуместным, а «Универсальный доступ» — использованным не по назначению;
- менеджеру буфера обмена, который только отправляет ⌘V, отказывали дважды;
- при этом похожие программы (Caramba Switcher, Lang Switcher) в App Store есть.

Что сделано, чтобы снизить риск: одно разрешение вместо двух (второе запрашивается, только если без него
система не даёт читать нажатия), запрос только по кнопке с объяснением, никаких сетевых прав, подробные
заметки для ревью. При отказе: ответить в Resolution Center со ссылкой на заметки и на аналоги в магазине;
если не поможет — распространять вне магазина с подписью Developer ID и нотаризацией (код менять не нужно,
достаточно другого способа экспорта).

## Релиз на GitHub

```bash
Tools/release-github.sh            # build/github/Raskladushka-<версия>.dmg и appcast.xml: Developer ID, нотаризация
Tools/release-github.sh --draft    # то же и черновик релиза v<версия> с текстом из AppStore/release-notes/
```

Порядок: поднять версию и номер сборки в `project.yml` → написать `AppStore/release-notes/<версия>.md` →
`open build/Build/Products/Debug/Raskladushka.app --args --uitest --spotlight` (все строки «ок») →
`Tools/release-github.sh --draft` → опубликовать черновик на GitHub → закоммитить и запушить `appcast.xml`
(по нему установленные копии узнают о новой версии) → `Tools/update-cask.sh <образ> <папка homebrew-tap>`
и запушить tap.

Что нужно на компьютере:
- настройки App Store Connect (`Tools/appstore/config.env`) — ими сборка отправляется на нотаризацию;
- сертификат «Developer ID Application» в связке ключей. Выпустить его может только владелец аккаунта; если
  Xcode отказывает («This operation can only be performed by the Account Holder»), сертификат выпускается на
  developer.apple.com → Certificates → «+» → Developer ID Application по файлу запроса;
- ключ подписи обновлений Sparkle в связке ключей (запись `raskladushka`; создаётся `generate_keys --account
  raskladushka`). Его открытая часть вписана в `project.yml` (`SUPublicEDKey`). Потеряете закрытую — уже
  установленные копии не примут обновления, сохраните его: `generate_keys --account raskladushka -x файл`;
- `dmgbuild` (`pip install dmgbuild`) — чтобы у окна образа был фон со стрелкой; без него образ получится простым.

Собирается цель `RaskladushkaDirect`: то же приложение плюс Sparkle. В цель для App Store (`Raskladushka`,
`Tools/release.sh`) Sparkle не входит — свой механизм обновления в магазине запрещён.

## Отказ по п. 2.4.5 и повторная отправка

23 ноября 2026 Apple отклонила 1.0.0: приложение просит «Универсальный доступ», но использует его не для
целей доступности. Обойти само разрешение нельзя: отправка нажатий (`CGEvent.post`) в macOS выдаётся только
через этот раздел настроек.

Что сделано в 1.3.0 для повторной отправки:
- разрешение необязательно: перевод выделенного через меню «Службы» работает без него, знакомство
  проходится без него;
- в сборке для магазина перехватчик всегда «только чтение»: настройка «Перехватывать системные сочетания»
  есть только в цели `RaskladushkaDirect`;
- вкладка «Доступность»: голос, размер и контраст подсказки, сочетание двойным нажатием;
- `review-notes.md` объясняет, для чего разрешение, кому оно помогает и как проверить без него;
- `metadata.md` и политика конфиденциальности приведены к версии 1.3.

Этого может не хватить: возражение Apple относится к самому разрешению. Запасные ходы: ответить в Resolution
Center со ссылкой на заметки и на похожие программы в магазине; выпустить в магазин издание вовсе без
разрешения (только меню «Службы»); остаться на GitHub и Homebrew.

Повторная отправка: `Tools/release.sh --upload` → дождаться обработки сборки →
`/usr/bin/python3 Tools/appstore/publish.py --submit --replace-screenshots`. Запускать именно системным
Python: у отдельно установленного Python 3.15 нет корневых сертификатов, и запросы к Apple не проходят.
Перед этим — опубликовать обновлённые страницы из `Site/` (политика конфиденциальности).
